The AAA review build (docs/reviews/aaa-2026-10-11/CONSENSUS.md) runs in 4 phases (D-066 to D-069) on branch `claude/aaa-review`. For each phase the code-reviewer writes `docs/reviews/aaa-2026-10-11/phaseN-code-review.md` with BLOCKING / NON-BLOCKING sections (file:line plus a concrete fix), and does not edit game code.

**Why:** the process per phase is developers, then test-engineer, then code-reviewer, then fixes, then the four reviewers consult, then the scribe. DECISIONS and REVIEW_QUEUE entries normally land after review, so missing D-06x entries at review time are flagged as non-blocking but required before commit.

**How to apply:** check the cross-cutting rules (draw-only, one FOV owner at most +6°, Reduced Motion off, no longer races, kind copy) for every phase. Client Roblox code here is written without Studio access, so look for Roblox API ordering pitfalls (for example, an Attachment's WorldPosition set before it is parented). Phase 1 review: [[phase1-findings]] lives in the repo file itself.

Useful check (Phase 2): pytest does not compile client scripts, so compile every `game/src/**/*.luau` with a Lune script using `require("@lune/luau").compile` — catches syntax errors and the 200-local/register limit (RaceController was at 195/200 top-level locals after Phase 2). Also check every consumer of a remote whose firing pattern changed (Phase 2's post-lock preview re-fired `LiveChances` and broke FanClient's cheer-close rule).

Phase 4 lesson: the session's injected commit attribution put "Claude <model name>" in the Co-Authored-By trailer (bed9d9e, 67f503f), breaking hard rule 5; policy_guard uses `git grep` so it never sees commit messages. Always check `git log --format=%B` trailers in reviews; never ask for history rewrite (rule 6), only fix forward.

Green Cash (D-070) lesson: "never sold" checks (trophy/rosette/Cup) in tests only regex ids and names; check item `emoji` fields too (a 🏵️ on a 💵 frame slipped through). Also check that a D-number isn't claimed by two features at once (tap gap is D-071 per plans-consensus.md, but its code said D-070).

Tap gap (D-071) lessons: the working tree changed under me mid-review (Ruling 2 gates landed while I read), so re-run `git status`/`git diff --stat` before writing the verdict. New client/shared modules are often left untracked (`??`) — a `WaitForChild` on a missing module yields forever silently, and CI's syntax_check only sees `git ls-files`; always flag untracked required files. Unreliable remotes sent "only on change" need a resend (lanes use `resend = 2`); harness gates that feed raw server values to a client rule (instead of the wire-filtered value) pass by construction. The session's injected commit trailer again named a model — flag every time.

Phase 3 lesson: "🔀 More choices" (RacePicker) is only reachable from the queue card, i.e. while the player is already in line. Any new picker action that passes a course to `JoinRace` must survive `joinQueue`'s early returns (same key → keep course; alone in line → card follows the pick). Phase 3's Race-with-friend broke on exactly that. Also, `pytest` now includes `tests/test_compile_all.py`, but still run the Lune compile when client files change.

Race-realism quick fixes (2026-10-12, branch claude/race-realism, review in docs/reviews/race-realism-2026-10-12/quickfix-code-review.md, BLOCKING/SHOULD/NIT format): a "cap = hh.WalkSpeed" guard was wrong because Gate Break's armed stall leaves WalkSpeed at gallop (TrainingState.speed = nil once the stick is released) and the horse stands still only because the stick is idle. Lesson: when code relies on a client value meaning "stopped", trace every state that sets it (TrainingRideClient gateFrame). Also check D-numbers against consensus.md (jump = D-074, not D-072).

Race-realism phase A (D-072) lessons: check that game config doesn't switch on an outcome change before its calibrated baseline lands (D-072 blocks on in GameConfig while TripBaseline.luau was still D-057, no style row → nil styleRow silently counts 0). "Learner floor"-style protections that trigger on "any press" become a free press-once edge (bounds presses count); check what the counter actually counts. Fixed-lanes flags must also guard the post-lock Luau-only path (Trip.cosmetic, Trip.submit), which Python parity never sees. Check that the sims' gates match the latest rulings file (phaseA-rulings.md), not just the plan.

Fun-and-return phase 1 (Find it, D-075; review in docs/reviews/fun-and-return-2026-10-12/phase1-code-review.md) lessons: client "latch" state (a chosen pointer/pill kept in a local var) bypasses pure gate functions on later renders. Tests of FindIt.pointerDue passed while StableBoard re-showed a stale pointer right after a race. Always check whether gates are re-evaluated for already-latched items. D-056 says "nothing tappable in the thumbstick zone" (touch dock anchors bottom-left), so watch for new first-slot buttons. Other agents' work (life arc) shared GameConfig and run_all.luau, so flag hunk-level staging. Phase 5 (visiting, D-079): policy_guard (git grep) can't see untracked files, so grep new ones by hand; "PolicyService answered" gates that read no field are reachability checks, not policy; a server-only stranger gate (policyOk) that the client walls can't see causes a sweep bounce loop. Lune single suites: a scratch runner that requires a relative path back into tests/luau works (cwd = repo). Phases 2-4 (D-076..D-078, phase2-4-code-review.md): when a new horse state (lent) is added, check every existing *Block function (rehomeBlock missed h.lent) and every card that lays out buttons by fixed x offsets (Home and Sell overlapped at -130). Per-id client "seen" caches break when the tracked value can drop (class path resets on league move-up).

Breeding (D-080, docs/reviews/breeding-2026-10-12/code-review.md) lessons: server `Profiles.notify` toasts immediately on the client (Hud Notice handler has no busy/results gate), so any post-race notify at runInSeconds+N lands over the results card; queue client-side like FirstRace. Client-derived flags (e.g. "surprise coat" = coat not in parents' current coats) break when a parent leaves and the view falls back to a default; store such flags at roll time. When memory < 1,200 MB, skip test runs and say so in the review header.
